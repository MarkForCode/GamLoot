# Architecture Decision Records

ADRs capture durable decisions, tradeoffs, and consequences. They are for decisions that future maintainers or AI agents should not have to rediscover.

## Naming

Use zero-padded numeric filenames:

```text
0001-short-decision-title.md
0002-next-decision.md
```

## When to Add an ADR

- Architecture boundary changes.
- New platform-wide workflow.
- New infrastructure pattern.
- Major technology choices.
- Decisions with meaningful tradeoffs or future consequences.

## Status Values

- `Proposed`
- `Accepted`
- `Deprecated`
- `Superseded`

Use `template.md` for new records.
